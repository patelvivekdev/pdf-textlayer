# pdf-textlayer

Adds an invisible, searchable text layer to a PDF from OCR boxes. All logic is Rust; the Python and Node.js packages are thin typed wrappers. The layout follows [liteparse](https://github.com/run-llama/liteparse).

## Layout

- `crates/pdf-textlayer`: the core library and the `pdf-textlayer` binary.
  - `lib.rs`: public types (`TextBox`, `ParsedPage`, `Options`, `Stats`, `Error`) and entry points (`write_text_layer`, `add_text_layer`, `make_searchable_pdf`).
  - `adapters.rs`: OCR JSON formats (`Adapter`). Add a format here, never in a language package.
  - `cli.rs`: the command line (`cli` feature). The binary, Python, and Node.js all call `cli::main`, so there is one CLI.
  - `overlay.rs`, `overlay_font.rs`, `native_text.rs`, `geometry.rs`, `metrics.rs`: drawing, the invisible font, native-word dedup, coordinates, and widths. `metrics_data.rs` is generated by `scripts/generate_metrics.py`.
- `crates/pdf-textlayer-python`: PyO3 module `pdf_textlayer._native`. Releases the GIL around every write.
- `crates/pdf-textlayer-napi`: napi-rs module. Writes run as `AsyncTask`s; errors get a `code` (`ENOENT`, `EIO`, `ERR_INVALID_PDF`, `ERR_INVALID_ARG_VALUE`).
- `packages/python`: PyPI package (`pdf_textlayer/`: `core.py` functions, `types.py` dataclasses, `cli.py`, `_native.pyi`). Tests use PyMuPDF to build fixtures and read output back.
- `packages/node`: npm package (`src/lib.ts` API, `src/native.ts` loader, `src/cli.ts`). Built with tsup to ESM + CJS.
- `examples/`: `scan.pdf` and its LiteParse JSON; the Rust, Python, and Node.js tests use them.
- `docs/`: the documentation site ([Blume](https://useblume.dev)). Pages are MDX in `docs/content`; sidebar groups are folders with a `meta.ts`. Deployed on Vercel with Root Directory `docs`.

## Changing the API

A new option or entry point goes into the core first, then into both binding crates, then into `core.py`/`types.py`/`_native.pyi` and `lib.ts`/`native.ts`, then the READMEs and `docs/content/reference`. Keep names parallel: snake_case in Rust and Python, camelCase in Node.js.

## Checks

```bash
make lint   # cargo fmt --check, clippy -D warnings, ruff, tsc
make test   # cargo test, pytest (packages/python), node --test (packages/node)
make docs   # blume validate + build (docs)
```

Use Conventional Commit messages (`feat:`, `fix:`, `docs:`, `ci:`, ...): release-please builds the changelog and the next version from them. Do not bump versions by hand; release-please updates every file listed in `release-please-config.json` in its release PR. `release-node.yml` adds the per-platform `optionalDependencies` at publish time.
